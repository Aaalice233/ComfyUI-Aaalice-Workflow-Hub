# 项目愿景

## 一句话定位

Aaalice Workflow Hub 是 ComfyUI 内的工作流订阅与版本管理中心：用户添加一个工作流仓库后，就能查看其中有哪些工作流、有什么更新、需要哪些自定义节点，并选择自己需要的内容进行下载或更新。

## 为什么要做

工作流作者通常把工作流、说明、更新日志和依赖信息分散在 GitHub、网盘、帖子或聊天记录中。用户很难回答这些问题：

- 我安装的是哪个版本？
- 作者最近更新了什么？
- 一个仓库里有多个工作流时，我能否只下载其中一个？
- 这个工作流缺少哪些自定义节点？
- 作者测试过的节点版本与我本地是否一致？
- 安装过程中现在进行到哪一步，失败原因是什么？

本项目希望把这些信息收拢到 ComfyUI 内，并让每一次环境变更都可见、可确认、可追踪。

## 目标用户

- 发布多个 ComfyUI 工作流并希望持续维护它们的作者。
- 希望方便获取更新，又不想盲目覆盖本地环境的工作流用户。
- 想建立私有或公共工作流目录规范的团队。

## 核心原则

### 工作流优先

项目管理的核心对象是“工作流产品”，而不是 Git 仓库本身。一个仓库可以包含多个不同用途、独立版本和独立依赖的工作流，用户可以按需订阅和下载。

### 作者可发布，用户可选择

作者通过一份可版本化的目录清单描述工作流、版本、资源和依赖。用户决定下载哪个工作流，以及是否执行节点安装、升级或降级。

### 先展示计划，再改变环境

插件必须在安装前列出将要执行的动作，例如安装、升级、降级、保持不变或发现冲突。任何第三方节点变更都需要用户确认。

### 复用生态能力

节点安装优先委托给 ComfyUI-Manager 等已有能力。本项目负责解析、比较、编排和展示，不重复实现完整的插件安装器。

### 进度必须真实

能够取得精确进度时才展示百分比；否则展示当前阶段、任务状态、实时日志和已完成数量，不能用动画伪装成真实进度。

### 安全默认值

首个可用版本仅支持受约束的公开工作流来源，不执行仓库脚本，不默认下载模型，不在启动时静默修改环境。

## 理想体验

1. 用户在插件中粘贴一个工作流仓库地址。
2. 插件读取仓库目录和 Release 信息，展示可订阅的多个工作流。
3. 用户查看介绍、预览图、版本、更新时间和更新日志。
4. 用户选择一个工作流并查看安装计划。
5. 插件对比本地自定义节点版本，明确列出保持、安装、升级、降级和冲突项目。
6. 用户确认后，插件下载并校验工作流包，再委托 Manager 执行节点变更。
7. 界面持续展示每个任务的状态、日志、失败原因和重试入口。
8. 安装完成后统一提示重启，并记录本地安装版本。

## 成功标准

- 用户不离开 ComfyUI 就能发现和更新作者发布的工作流。
- 同一仓库中的多个工作流可以独立下载、更新和卸载本地记录。
- 更新内容和环境变更在操作前后都清晰可见。
- 依赖对齐失败时能说明具体项目和原因，而不是给出笼统错误。
- 工作流作者可以用稳定、可验证的仓库格式发布内容。

## 当前边界

项目目前仅完成初始化，本文描述的是目标方向，并不代表功能已经实现。

首个版本暂不包含：

- Comfy Registry 发布。
- 私有 GitHub 仓库和其他需要登录的来源。
- 模型文件自动下载。
- 任意 Git 仓库作为节点来源。
- Python、系统依赖或完整运行环境的自动还原。
- 启动时静默更新工作流或第三方节点。
