# 项目愿景

ComfyUI-Aaalice-Workflow-Hub 是 ComfyUI 内的双向工作流中心：作者在插件里发布，订阅者在插件里发现、查看并下载不同版本。

## 目标

- 让工作流、版本、说明、更新日志和依赖声明形成可校验的公开协议。
- 让一个仓库承载多个可独立发布、下载和归档的工作流产品。
- 让所有节点环境变更先形成计划，再由用户确认并全局串行执行；Git 与历史 Registry Manager 依赖按各自锁定来源补全，远端引用过期和本地独有提交都应无损处理，网络检查、进度、日志和结果必须可见且可恢复，ComfyUI-Manager 与 Workflow Hub 本身不作为工作流依赖。
- 让发布、管理和下载失败有可定位的原因，已发布 Release 与已下载旧版本不被覆盖；发布和管理变更都通过持久化操作显示真实阶段、日志和错误。
- 让订阅者在下载前知道工作流的打包内核与当前 ComfyUI 内核、插件依赖是否匹配，并在风险存在时得到可跳过或可同步的明确选择。

## 当前边界

当前实现包含公共 GitHub 仓库订阅、GitHub Device Flow、可浏览仓库存档、Release 分发、原子目录提交、可配置间隔的后台版本通知、安全包下载、历史版本保留、Git/Manager 双来源插件依赖计划与全局串行补全（宿主基础插件不计入依赖）、本地未提交内容与独有提交备份、下载前内核与插件依赖防误操作检查、GitHub Flavored Markdown 更新日志渲染与安全过滤、网络自检、Python requirements 处理、持久化安装操作、双语界面和用户隔离存储。

当前范围不包含私有仓库、其他 Git 服务、模型或 LoRA 自动下载、任意节点 Git 地址、遥测和侧边栏，也不为工作流提供 Comfy Registry 分发或自动发布流程（插件本体经 Registry 分发属于交付渠道，不在产品功能内）。发布器自动识别 Lora Manager 的 LoRA 引用；检测到后仅显示提醒，不阻止作者继续发布，但工作流包和下载页面都不提供 LoRA 依赖。

## 原则

- 工作流产品是核心对象，仓库只是发布载体。
- 订阅不等于下载，下载不等于修改节点环境。
- 发布版本不可覆盖；展示资料、归档状态和版本更新日志可以更新，版本只能由有写权限的作者通过管理功能删除。
- 能取得下载字节时才展示百分比；发布和管理展示真实的阶段状态，插件补全展示真实的插件级进度、安装日志和错误状态，不伪造百分比。
- 不执行仓库或工作流包中的脚本；工作流包只可附带画布、子图和侧边栏图像控件引用的本地图像，不把模型或第三方节点代码装入主包。
