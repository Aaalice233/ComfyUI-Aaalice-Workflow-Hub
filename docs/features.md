# 功能细节

## 文档状态

本文件是功能设计草案。除“项目骨架”外，下面的功能均尚未实现。功能落地时必须同步更新状态和实际行为。

## 1. 工作流源管理

用户可以添加、编辑、启用、停用和移除工作流源。

首个版本计划支持：

- GitHub 公共仓库地址。
- 固定仓库默认分支上的目录清单。
- GitHub Releases 中发布的工作流包。
- 手动刷新与带缓存的定时检查。

添加来源时应验证：

- URL 是否属于允许的来源。
- 仓库是否公开且可访问。
- 目录清单是否存在、版本是否受支持。
- 清单中声明的资源地址是否仍属于允许范围。

移除来源只删除订阅和缓存，不应静默删除用户已经下载的工作流文件。

## 2. 多工作流目录

一个仓库可以发布多个互相独立的工作流。目录页至少展示：

- 名称、标识符和用途说明。
- 当前版本、发布时间和兼容的 ComfyUI 范围。
- 预览图、作者和标签。
- 是否已安装、本地版本和是否存在更新。
- 包大小、依赖数量和更新日志入口。

用户可以按名称、标签、安装状态和更新状态筛选，并只下载自己需要的工作流。

每个工作流使用稳定且在仓库内唯一的 `id`。更改展示名称不得导致本地记录丢失。

## 3. 仓库目录协议

计划在仓库根目录使用 `workflow-catalog.json` 作为机器可读入口。字段在实现前仍可调整，预期结构如下：

```json
{
  "schema_version": 1,
  "repository": {
    "name": "Example Workflows",
    "author": "example"
  },
  "workflows": [
    {
      "id": "portrait-basic",
      "name": "Portrait Basic",
      "latest_version": "1.2.0",
      "release_tag": "portrait-basic-v1.2.0",
      "channel": "stable"
    }
  ]
}
```

Release 中的工作流包计划包含：

```text
manifest.json
workflow.json
README.md
CHANGELOG.md
preview.png
```

其中只有 `manifest.json` 和 `workflow.json` 是必需文件。包格式确定后必须补充独立的协议文档和 JSON Schema。

## 4. 工作流版本与更新日志

插件记录每个已下载工作流的：

- 来源、工作流 `id` 和安装版本。
- 下载时间、资源校验值和本地文件位置。
- 用户是否对工作流文件做过本地修改。

更新检查比较仓库最新版本与本地记录，支持：

- 查看最新版本。
- 查看从本地版本到目标版本的更新日志。
- 下载指定版本，而不只支持最新版。
- 在覆盖前提醒本地文件已修改。
- 下载失败后保留原文件和原版本记录。

版本号优先使用语义化版本。无法解析的版本只允许作为显示值，不能参与自动升级或降级判断。

## 5. 工作流打包与解包

原先“解包子图以帮助发现缺失节点”的需求不直接作为核心功能保留。是否需要该兼容能力，应先验证当前 ComfyUI-Manager 是否仍无法识别子图中的缺失节点。

首个版本计划把“打包”定义为安全的工作流发布包：

- 收集工作流 JSON、说明、预览图、更新日志和依赖清单。
- 校验文件名、大小、格式和清单一致性。
- 生成校验值，产出可上传到 Release 的压缩包。
- 不打包模型、第三方节点代码、Python 环境或用户隐私配置。

“解包”只负责校验并安装上述受约束的工作流资源，不执行包内脚本，也不把文件写到允许目录之外。

如果后续确认 Manager 已能完整分析子图，项目不再维护旧式展开子图方案；如果问题仍存在，则把兼容扫描做成独立、可测试的解析模块，而不是修改用户原工作流。

## 6. 自定义节点依赖清单

每个工作流版本可以声明作者测试过的自定义节点版本，优先使用 Comfy Registry 节点标识和版本：

```json
{
  "custom_nodes": [
    {
      "registry_id": "example-node-pack",
      "version": "1.4.2",
      "required": true
    }
  ]
}
```

插件比较清单与本地环境后生成安装计划：

- `keep`：版本已满足。
- `install`：本地未安装。
- `upgrade`：本地版本低于目标。
- `downgrade`：本地版本高于作者锁定版本。
- `enable`：已安装但被禁用。
- `conflict`：无法安全对齐或多个工作流要求互相冲突。
- `unknown`：无法可靠识别本地版本。

默认不强制环境完全对齐。降级、冲突和未知状态必须单独提醒，用户可以取消或跳过可选依赖。

Git 提交哈希或任意仓库 URL 只能作为未来的高级模式讨论，不能在首个版本绕开 Registry 安全边界。

## 7. ComfyUI-Manager 集成

本项目不自行复制完整节点安装逻辑，而是建立 Manager 适配层：

- 启动时检测 Manager 是否存在及其接口版本。
- 优先使用公开、稳定的任务接口。
- 接口不兼容时明确提示，不猜测调用内部实现。
- 把 Manager 返回的任务状态和日志转成统一界面状态。
- 所有环境修改完成后统一提示一次重启。

如果 Manager 没有提供所需的版本安装、进度或取消接口，插件应明确降级能力。例如只能展示阶段日志时，不显示虚假的精确百分比。

## 8. 安装进度与操作日志

安装面板按任务展示：

- 等待、下载、校验、安装、完成、失败、取消。
- 当前节点名称、目标版本和执行动作。
- 已完成任务数与总任务数。
- Manager 返回的实时日志。
- 失败原因、原始错误摘要和重试入口。

精确字节进度只用于能够读取内容长度的下载。安装阶段如果下游没有提供百分比，就展示不确定进度和真实日志。

日志应默认隐藏访问令牌、本地隐私路径和其他敏感值，并允许用户复制经过脱敏的诊断信息。

## 9. 并发策略

并行不等于同时执行所有安装：

- 元数据请求、预览图和相互独立的包下载可以设置较小并发数。
- 校验可以并行，但要限制 CPU 和磁盘占用。
- 会修改 `custom_nodes`、Python 环境或 Manager 状态的节点安装任务默认串行。
- 重启提示只在整个批次结束后出现一次。

在确认 Manager 明确支持并发安装且不会争用 Git、pip、锁文件或重启状态前，不开放并行节点安装。

## 10. 安全与完整性

必须具备：

- HTTPS 与来源主机限制。
- 压缩包路径穿越、符号链接和解压炸弹防护。
- 单文件、单包和总下载大小限制。
- Release 资源校验值验证。
- JSON Schema 与字段长度校验。
- 临时目录下载，校验成功后再原子替换目标文件。
- 失败时保留旧版本，不把半成品记录为安装成功。
- 不执行工作流包中的脚本、可执行文件或动态 Python 代码。
- 修改第三方节点前必须展示计划并取得确认。

## 11. 本地数据

订阅、缓存、安装记录和日志应写入 ComfyUI 提供的用户数据目录，不硬编码 `user/default`，也不把运行数据写回插件仓库。

需要区分：

- 可随时重建的远端缓存。
- 用户的订阅和偏好。
- 工作流安装记录。
- 一次安装批次的操作日志。

卸载插件不应自动删除用户下载的工作流。

## 12. 界面规划

计划提供以下页面：

- **来源**：添加仓库、检查连接、刷新和查看错误。
- **工作流列表**：搜索、筛选、预览、安装和更新。
- **工作流详情**：版本、更新日志、依赖和历史版本。
- **安装计划**：展示全部环境变更并让用户确认。
- **任务中心**：查看实时状态、日志、失败项和重试。
- **设置**：更新检查频率、下载并发数、日志保留和实验功能。

界面应保持轻量，不用高对比度边框切割内容；加载、选中、失败和危险操作必须有明确反馈。
