# 功能与状态

本文件描述仓库当前实现。规划外能力不会在界面中伪装成可用。

## 已实现

### 顶栏和内置页面

- Frontend `actionBarButtons` 注册顶栏按钮，最低 Frontend `1.33.9`。
- 普通点击在 ComfyUI 内使用非全屏面板加载 `/workflow-hub`；面板不重复创建外层标题栏，关闭入口位于工作流中心自身顶栏；`Shift+点击` 打开独立窗口。
- 工作流中心采用黑灰桌面工作台布局：顶栏以居中 Switcher 切换订阅和发布，滑块、页面动效与强调色同步变化；订阅使用蓝色强调色，发布使用低饱和青绿色强调色。
- 界面语言自动跟随 ComfyUI 的 `Comfy.Locale` 设置；简体及繁体中文使用中文界面，其余 ComfyUI 语言使用英文界面。
- 用户可见文案按运行面集中在 `frontend/src/i18n.ts` 和 `web/comfyui/i18n.js`；动态内容使用命名参数插值，页面组件和宿主桥接代码中不维护中英文条件分支。
- ComfyUI 宿主后台按每位用户的设置优先从 GitHub Contents API 检查订阅清单；公共 API 限流时仅对只读清单回退到带强制刷新参数的 GitHub Raw 地址。设置页可关闭自动更新检测，或将检查间隔配置为 1–168 小时。已有工作流出现更高版本时，合并显示一个 5 秒自动关闭的 ComfyUI 内置 Toast；检查失败不会消耗本次周期，宿主在下一次到期时自动重试。
- 订阅页以搜索和筛选为主入口，订阅源按需展开管理。
- 工作流卡片和详情页可直接打开 GitHub 中对应的工作流目录；详情页可切换历史版本并查看当前版本变更记录，版本详情顶部集中显示内核、插件和随包图片状态，明细通过悬浮提示或点击查看。
- 订阅页工具栏提供始终可见的“刷新全部”，订阅源面板仍可单独刷新指定仓库。
- 详情页采用紧凑的项目摘要、版本导航和单版本工作区；封面仅作缩略图，历史版本不再纵向重复展开，空资源以计数呈现。
- 更新日志支持 GitHub Flavored Markdown 的标题、列表、表格、代码块、引用、任务列表、链接和图片，并对远程清单中的 HTML 与链接协议做安全过滤；长日志限制在较大的独立滚动区域内，不会挤压版本信息和顶部资源状态控件。
- 发布版本自动记录作者当前的 ComfyUI 内核版本；订阅详情会与使用者当前内核比较，不匹配时在下载操作上方显示风险警告，但仍允许用户自行下载。
- 未登录时发布页只显示 GitHub 授权引导，不读取仓库或展示发布表单；登录后自动读取当前画布，并按“确认资源、填写信息、确认发布、完成”四个阶段推进。发布成功后自动进入完成页，展示仓库、版本、Release 链接和操作时间。
- Vue 3、TypeScript、Vite 源码和生产构建产物同时交付。

### 订阅和下载

- 添加、刷新和移除公共 GitHub 订阅源。
- GitHub Contents API 清单按用户写入持久化本地缓存，以 ETag 或内容哈希判断变化；公共 API 限流时仅对只读清单回退到带强制刷新参数的 GitHub Raw 地址。每次 ComfyUI 启动后的首次显示先完成强制远程验证，后续网页重新打开可先显示带用户作用域的近期快照并继续验证；目录缓存不参与 ComfyUI 原生更新通知的周期判断。手动刷新和发布者管理操作完成后的刷新也使用强制远程请求，且同一订阅源的刷新串行执行。
- 聚合目录、搜索、下载/更新/归档筛选、详情和历史版本。
- 下载 GitHub Release 包并验证 HTTPS 主机、大小、SHA-256、ZIP 条目、路径、符号链接、压缩比和解压总量。
- 每个版本写入独立文件；同版本文件内容不一致时报完整性错误。
- 下载复用持久化 `download` 操作，活动面板显示下载字节进度、校验、写入和失败状态；完成提示和详情页都可直接打开工作流目录。
- 读取目录时核对已下载记录与本地文件；文件被用户从 ComfyUI 或资源管理器删除后，失效记录自动清理。
- 移除订阅不删除已下载文件；本地版本只能由用户明确删除。

### 发布

- GitHub App Device Flow 登录：授权页分两步突出显示验证码和 GitHub 入口，验证码支持一键复制，授权完成后自动进入发布界面；凭据使用 keyring/session 降级存储，GitHub 返回 401 时自动清除失效凭据并提示重新登录。
- 发布器仅使用当前 ComfyUI 画布，不提供文件选择器；页面顶部持续显示捕获到的工作流文件名，避免误发其他工作流。
- 发布流程采用单列四阶段发布控制台，通过底部前进/返回操作切换，不提供草稿保存；前三阶段分别确认资源、填写发布资料和复核后校验或发布，发布成功后自动进入完成页，提供查看活动、管理已发布内容和再次发布入口。
- 活动面板对发布和待同步续传显示“校验、创建 Release、上传、发布 Release、写入仓库”五个阶段的分段进度条和当前阶段；管理页的资料编辑、归档、更新日志和删除使用同一活动面板显示与实际动作匹配的阶段，不虚构精确百分比；每条活动显示记录时间，已完成或失败的记录可逐条删除或一键清除，进行中的操作不可删除；失败时保留状态、日志和错误信息。
- 发布器读取当前画布文件名末尾的 `-v{版本}` 或 `_v{版本}`，自动填充工作流名称和版本；订阅者下载后按同一分隔符保存为带版本号的独立文件。
- 资源确认阶段按插件依赖、随包图片和 LoRA 分组完整展示；插件列表扫描 `custom_nodes` 下的 Git 工作副本，ComfyUI-Manager 和 ComfyUI-Aaalice-Workflow-Hub 作为宿主基础插件自动忽略，由作者取消勾选与工作流无关的插件，不把原始节点类型当作插件发布。
- Git 依赖记录 GitHub 地址和完整 Git commit；历史 Registry 依赖记录 Registry ID 和版本并沿用 ComfyUI-Manager 补全。两个宿主基础插件不会写入工作流依赖或进入补全计划。
- 订阅详情页按版本展示 ComfyUI 内核、已发布的插件和图片；版本详情顶部集中显示内核、插件和随包图片状态，点击状态控件查看可操作的完整明细，页面不提供 LoRA 依赖数量或下载入口。
- 仓库选择会保存在浏览器本地；再次打开发布页时优先恢复上次选择，记录不存在或已失效时自动选择第一个可用仓库。仓库名称、作者和说明直接读取 GitHub，不要求重复填写。
- 类别、名称和版本均为必填；发布器读取仓库现有类别，也允许直接输入新类别，不提供树形嵌套。
- 工作流 ID 由类别和名称自动生成；类别与名称同时匹配已有工作流时沿用原 ID 并发布新版本，无需额外选择“发布方式”。
- 发布时可选上传封面图（PNG、WebP 或 JPEG，不超过 10 MiB）；同一份预览文件保存进版本目录与 ZIP，同时作为该版本预览和工作流封面，不带封面发布则保留原封面。
- 校验版本、自动生成的稳定 ID、Release tag、清单和依赖声明。
- ComfyUI 兼容版本由服务端在校验和发布时重新检测并写入，不能由前端手工覆盖。
- 创建 Draft Release、上传 ZIP、发布 Release，再通过 Git Data API 原子提交版本目录、产品资料、README 和根清单；新发布版本不上传 LoRA。
- 仓库并发冲突重新获取并合并一次；Release 已发布而仓库存档失败时记录待同步数据，续传从已校验 ZIP 恢复，不重复扫描资源或创建 Release。

### 管理

- 管理页面向对仓库有写权限的作者：选择仓库后列出全部已发布工作流（含已归档），并可直接打开所选 GitHub 仓库原址；订阅页面只提供下载与查看，不含任何仓库操作。
- 编辑工作流的名称、类别、简介、说明和标签；改名或改类别时在一次原子提交中迁移仓库目录。
- 归档或取消归档工作流；归档工作流在订阅侧仍可见但明确标记。
- 编辑已发布版本的更新日志，并同步改写对应 GitHub Release notes。
- 已发布版本的 Git 插件依赖可以后期改钉：逐个从源仓库最近 commit 中选择、单独或全部一键切换到最新；后端校验新 commit 真实存在后重打包 Release 资产内的 manifest 并同步更新目录与校验值；Registry 与手动依赖不支持在线改钉。
- 归档、资料编辑、更新日志编辑和删除均作为持久化异步操作执行；操作进行时管理操作锁定，完成后强制重新验证对应订阅源并刷新管理列表和订阅缓存，失败时不静默清理并在活动面板保留错误。
- 删除单个版本或整个工作流需明确确认；删除同时移除对应 Release、tag 和仓库目录，删除最后一个版本即移除整个工作流。订阅者已下载的本地副本不受影响。

### 依赖与安全

- Registry 依赖与手动依赖分开声明。
- 依赖计划状态：`keep/install/upgrade/downgrade/conflict/unknown/manual`；版本对齐默认开启，关闭后只提示版本差异，不执行升级或降级。
- 打开工作流详情时自动后台检查依赖，并在同一份插件列表中直接标注安装状态（绿色已安装、未安装、需切换版本、需手动等）；点击下载时会强制重新检查一次内核和插件依赖，发现缺失、版本不一致或无法检查时先弹出防误操作提示。
- 下载前检查弹窗允许用户取消、跳过检查直接下载，或同步可自动处理的插件；同步完成后自动重新检查，内核版本仍需用户手动更新并重启，Git 与 Manager 使用不同颜色的来源徽章。
- 用户确认后只执行勾选的安装或版本切换；Git 依赖按锁定 commit 执行，Manager 依赖交给兼容的 ComfyUI-Manager 队列处理，手动依赖和冲突不会自动执行。
- 点击执行后先检查 GitHub/Comfy Registry 网络连通性；失败会在同一进度条和日志中提示检查网络、VPN 或 TUN 模式。
- 启动时自动继承 Windows 系统代理并注入 Git/pip 子进程与 HTTP 客户端（`HTTP_PROXY`/`HTTPS_PROXY`/`NO_PROXY`，本机回环地址始终绕过），显式设置的环境变量优先，不开 TUN 也能完成插件补全；代理状态随 `/status` 返回供诊断。
- Git clone/fetch/checkout 可安全并行执行，checkout 钉在锁定 commit 但保留本地分支与 upstream 跟踪（不产生游离态 HEAD），用户可用启动器或 Manager 自行检测和拉取更新，重新补全时会重置回锁定 commit；commit 已对齐但处于游离态的历史工作副本会在检测中提供补全，将其挂回分支跟踪；存在未推送提交的工作副本会被拒绝切换并提示先处理。Python `requirements.txt` 安装按插件完成后串行执行并计入进度；Manager 的 post-install 依赖处理由 Manager 执行并回传结果。两种路径共用同一个异步安装操作、逐插件状态、实时日志和持久化历史，完成后提示重启 ComfyUI。
- 依赖弹窗的安装按钮、进度条和逐插件日志固定在插件列表上方；进度展示只跟随本次面板会话中启动的安装操作，历史已完成或失败的操作不会在重开面板后残留显示，手动重新检查依赖时同步清除已结束的执行展示。
- 订阅者依赖弹窗、发布资源确认和下载前检查的插件条目都提供来源页面跳转：Git 依赖打开 GitHub 仓库，Registry 依赖打开 Comfy Registry 节点页。
- 内核版本只做兼容性检测与提示（详情页顶部状态控件和详情弹窗展示当前版本、工作流要求和对齐状态），不自动切换 ComfyUI 内核；版本未声明或无法可靠比较时明确显示未知状态。
- Manager 不可用时仍允许下载工作流。
- 自动扫描并打包画布节点、子图和侧边栏图像控件引用的本地图像（包括 `LoadImage`、`LoadImageMask`、`LoadImageOutput` 及兼容的 image widget），安装时按原引用写入 ComfyUI 根 `input/` 目录，不改写工作流引用；工作流文件直接写入当前用户的 `workflows/` 目录。
- 随包图片同时写入版本目录的 `inputs` 字段，使订阅用户无需下载 ZIP 即可确认图片名称、大小和引用节点。
- 识别 Lora Manager 引用；检测到 LoRA 时仅在资源区域显示数量和提醒，不阻止作者进入下一步或发布。
- LoRA 不会被打包或下载；发布器检测到 LoRA 引用时仅显示提醒，供作者在发布前确认工作流不会携带该依赖。
- 内置页面使用稳定的前端资源入口并禁止缓存页面壳；嵌入弹窗每次打开都会刷新入口，且避免在 iframe 祖先层使用会导致 Electron 黑屏的背景模糊合成。
- 写接口限制同源、20 MiB 请求体和当前 ComfyUI 用户；携带 JSON 请求体时必须使用 JSON Content-Type。
- 操作日志脱敏，不包含遥测。

## 不在当前范围

- 私有 GitHub 仓库、GitLab、Gitee 或任意资源主机。
- 覆盖已发布 Release 资产（版本只能整体删除，不能替换内容）。
- 自动下载模型或 LoRA。
- 执行工作流仓库脚本。
- 自动安装、升级、降级、启用节点。
- 面向工作流的 Comfy Registry 分发，或在插件内自动发布 Registry 的流程。
