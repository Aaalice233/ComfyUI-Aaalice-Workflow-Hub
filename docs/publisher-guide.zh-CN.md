# 作者发布指南

先在 ComfyUI 中打开准备发布的工作流，再从顶栏进入“工作流中心”。发布页会自动读取当前画布并持续显示工作流文件名。

发布表单按三个阶段推进：

1. **确认资源**：检查自动识别的 ComfyUI 内核版本、`custom_nodes` 下的 Git 插件仓库、画布/子图/侧边栏图像控件引用的图片和 Lora Manager 引用。内核版本由服务端读取，不能手工修改；检测到 LoRA 时只显示提醒，不阻止继续发布，也不会自动打包或下载 LoRA。
2. **填写信息**：发布器自动恢复上次使用的公共仓库，无记录或记录失效时选择第一个可用仓库；如果当前画布文件名以 `-v0.1` 或 `_v0.1` 形式结尾，发布器会自动解析并填入名称和版本；随后填写必填的单层类别、名称、`1.12` 或 `1.12.3` 形式的版本和更新日志。类别与名称同时匹配已有工作流时自动发布新版本，否则新建工作流；稳定 ID 自动处理。此阶段可选上传一张封面图（PNG、WebP 或 JPEG，不超过 10 MiB），同时作为工作流卡片封面和该版本预览；不带封面发布新版本时保留原封面。
3. **确认发布**：复核仓库、工作流、版本、封面、内核和资源数量，再执行校验或发布。

需要创建新仓库时，可在第二阶段展开“新建仓库”；新仓库仍需加入公开的 [Aaalice Workflow Hub Publisher](https://github.com/apps/aaalice-workflow-hub-publisher) installation。封面为可选项，未上传封面的工作流在工作流中心显示占位图标。发布顺序为 Draft Release、ZIP 上传、Release 发布，再原子提交“类别 / 名称 / 版本”仓库存档、产品资料、README 和根清单。活动面板会用五段进度条显示校验、创建 Release、上传、发布 Release 和写入仓库的当前阶段；这是阶段指示而非虚构的精确百分比，并会保留失败日志和错误。

发布版本不可覆盖；删除版本或整个工作流需要明确确认，并会同时移除对应 Release、tag 与仓库目录。仓库并发修改会自动合并重试一次；若 Release 已发布但仓库存档失败，“待同步发布”会从已生成的 ZIP 恢复，不要求本地图片仍然存在。

## 管理已发布内容

“管理工作流”页面向对仓库有写权限的作者：选择仓库后可以直接打开所选 GitHub 仓库原址，编辑工作流资料（改名或改类别会在一次原子提交中迁移仓库目录）、归档或取消归档、编辑任意版本的更新日志（同步改写 Release notes），以及删除单个版本或整个工作流。删除最后一个版本时整个工作流一并移除；订阅者已下载的本地副本不受影响。订阅页面的详情只提供下载与查看，不含任何仓库操作。

插件依赖同时扫描当前 `custom_nodes` 下的 Git 工作副本和 ComfyUI-Manager 已安装插件，列表用不同颜色的 Git/Manager 徽章区分来源；作者仍需取消勾选与工作流无关的项。列表中的名称都是插件仓库，不会把节点类型冒充插件。

Git 依赖记录 GitHub 仓库地址和完整 40 位 commit，Manager 依赖记录 Registry ID 和版本。用户补全时先检查网络环境，再由 Git 并行 clone、fetch 和 checkout Git 依赖，并在同一安装详情中执行和记录 Python `requirements.txt`；Manager 依赖则交给兼容的 ComfyUI-Manager 队列及其 post-install 处理。两种安装方式都在同一个依赖面板和活动详情面板中显示进度、插件状态、原始日志和错误结果，历史记录会持久化保存。

包和目录细节见[协议](protocol.md)，安全限制见[安全边界](security.md)。
