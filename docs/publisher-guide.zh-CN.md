# 作者发布指南

先在 ComfyUI 中打开准备发布的工作流，再从顶栏进入“工作流中心”。发布页会自动读取当前画布并持续显示工作流文件名。

发布表单按三个阶段推进：

1. **确认资源**：检查自动识别的 ComfyUI 内核版本、ComfyUI-Manager 插件包、画布/子图/侧边栏图像控件引用的图片和 Lora Manager 引用。内核版本由服务端读取，不能手工修改；检测到 LoRA 时只显示提醒，不阻止继续发布，也不会自动打包或下载 LoRA。
2. **填写信息**：发布器自动恢复上次使用的公共仓库，无记录或记录失效时选择第一个可用仓库；如果当前画布文件名以 `-v0.1` 或 `_v0.1` 形式结尾，发布器会自动解析并填入名称和版本；随后填写必填的单层类别、名称、`1.12` 或 `1.12.3` 形式的版本和更新日志。类别与名称同时匹配已有工作流时自动发布新版本，否则新建工作流；稳定 ID 自动处理。此阶段可选上传一张封面图（PNG、WebP 或 JPEG，不超过 10 MiB），同时作为工作流卡片封面和该版本预览；不带封面发布新版本时保留原封面。
3. **确认发布**：复核仓库、工作流、版本、封面、内核和资源数量，再执行校验或发布。

需要创建新仓库时，可在第二阶段展开“新建仓库”；新仓库仍需加入公开的 [Aaalice Workflow Hub Publisher](https://github.com/apps/aaalice-workflow-hub-publisher) installation。封面为可选项，未上传封面的工作流在工作流中心显示占位图标。发布顺序为 Draft Release、ZIP 上传、Release 发布，再原子提交“类别 / 名称 / 版本”仓库存档、产品资料、README 和根清单。

发布版本不可覆盖；删除版本或整个工作流需要明确确认，并会同时移除对应 Release、tag 与仓库目录。仓库并发修改会自动合并重试一次；若 Release 已发布但仓库存档失败，“待同步发布”会从已生成的 ZIP 恢复，不要求本地图片仍然存在。

## 管理已发布内容

“管理工作流”页面向对仓库有写权限的作者：选择仓库后可以编辑工作流资料（改名或改类别会在一次原子提交中迁移仓库目录）、归档或取消归档、编辑任意版本的更新日志（同步改写 Release notes），以及删除单个版本或整个工作流。删除最后一个版本时整个工作流一并移除；订阅者已下载的本地副本不受影响。订阅页面的详情只提供下载与查看，不含任何仓库操作。

插件依赖直接列出当前用户已安装的 Manager 插件包，作者必须取消勾选与工作流无关的项。列表中的名称都是插件包，不会把节点类型冒充插件。

自己从 GitHub clone 用于开发的插件分两种处理：

- Manager 能识别到 `cnr_id`：发布 Registry ID，界面显示本地 Git 提交用于提醒作者，但不锁定该 commit；普通用户仍通过 Manager 安装可用版本。
- 没有 `cnr_id`：发布为 GitHub 手动依赖并保留仓库地址，因为 Manager 没有可供普通用户安装的 Registry 身份。

包和目录细节见[协议](protocol.md)，安全限制见[安全边界](security.md)。
