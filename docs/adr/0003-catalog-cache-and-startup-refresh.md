# ADR-0003：目录缓存与启动刷新

- 状态：已接受
- 日期：2026-08-04

## 背景

订阅目录本身已经按用户保存 GitHub Raw 清单缓存，但页面打开时仍会重新请求订阅源和聚合目录。启动后台刷新与页面首次加载并行时，刷新完成还会再次触发整页加载，造成竞态、重复请求和加载状态闪烁。

## 决策

- 保留按用户隔离、以 ETag 和内容哈希校验的持久化源缓存；它是 GitHub 访问和离线回退的事实来源。
- 在浏览器中按后端返回的用户作用域保存目录快照，只缓存订阅源和聚合工作流数据，不缓存凭据、操作日志或发布数据。快照在短时间内视为新鲜，过期后采用 stale-while-revalidate；缓存不可用时不影响实时请求。
- 前端对目录请求和完整初始化使用 single-flight，并以递增版本号处理刷新期间的写入，避免旧请求覆盖手动刷新或订阅变更后的结果。
- 启动刷新接口返回目录/订阅状态是否发生变化。页面首次加载先显示缓存，只有状态确实变化时才执行无加载闪烁的静默目录更新；操作轮询只有在会改变目录的操作完成后才刷新目录。
- “刷新全部”、单源刷新、添加/移除订阅和本地版本删除都会主动使前端快照失效，并等待新的目录结果；手动刷新仍是获取最新内容的明确入口。

## 结果

页面重开时可以立即复用当前用户的目录，正常情况下不再重复拉取相同的订阅数据；远程目录变化、用户主动操作和下载状态变化仍会收敛到服务端真实状态。缓存是优化而非数据来源，清理、配额不足、旧版本或隐私模式下的存储失败都会自动退回实时 API 请求。
