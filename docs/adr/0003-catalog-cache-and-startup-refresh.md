# ADR-0003：目录缓存与启动刷新

- 状态：已接受
- 日期：2026-08-04

## 背景

订阅目录按用户保存远程清单缓存，但浏览器快照、后端源缓存和 ComfyUI 原生更新通知曾分别刷新，导致页面刷新后仍可能展示旧目录，或者旧的远程响应覆盖新的缓存。

## 决策

- 保留按用户隔离、以 GitHub Contents API 的 ETag 和内容哈希校验的持久化源缓存；已登录 GitHub 时清单读取使用用户 token（凭据 401 时回退匿名）；Contents API 触发公共限流时，仅对只读清单回退到带唯一查询参数的 GitHub Raw 请求，避免订阅功能因匿名 API 配额耗尽而不可用。
- 浏览器按后端返回的用户作用域保存版本化目录快照，只缓存订阅源和聚合工作流数据，不缓存凭据、操作日志或发布数据。快照只负责快速首屏和失败回退，不能作为刷新成功的依据；缓存版本变化时自动丢弃旧快照。
- 每次 ComfyUI 启动后的首次页面显示保持加载态，先调用 `POST /subscriptions/refresh-all` 对全部订阅源执行强制远程校验，再用同一响应渲染目录；后续重新加载可先显示快照，同时执行带 ETag 的远程校验。手动刷新始终使用强制请求，因此首次显示、网页刷新和手动操作都不会把浏览器快照当成权威数据。
- “刷新全部”复用同一个强制刷新接口；单源刷新、添加/移除订阅和发布者管理完成后的刷新都会使目录请求版本失效并等待新的结果。强制 API 请求不发送旧 ETag，并使用 `Cache-Control: no-cache`。
- 同一用户、同一订阅源的刷新仍由后端锁串行执行；前端目录请求使用 single-flight 和递增版本号，避免旧请求在强制刷新后回写旧数据。刷新接口返回远程刷新后的订阅源和聚合目录，避免再次读取尚未收敛的旧快照。
- ComfyUI 原生更新通知使用独立的每用户检查状态，不读取浏览器目录快照；自动检测默认开启，检查间隔可在 1–168 小时内配置。到期检查同样执行强制远程刷新（优先 Contents API，限流时使用只读 Raw 回退），成功后才记录周期；网络或清单失败会在短暂退避后重试。宿主根据后端返回的下一次检查时间调度检查，设置变更会立即重新计算。

## 结果

首次显示在强制远程校验完成后才展示目录，后续重开可以立即显示当前用户的最近目录并在后台完成一次带 ETag 的远程校验；远程目录变化、用户主动操作和下载状态变化都会收敛到服务端真实状态。缓存是优化和失败回退，不是远程数据来源；清理、配额不足、旧版本或隐私模式下的存储失败不会阻止实时刷新。
