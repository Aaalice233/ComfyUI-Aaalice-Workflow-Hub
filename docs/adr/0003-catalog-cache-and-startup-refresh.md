# ADR-0003：目录缓存与启动刷新

- 状态：已接受
- 日期：2026-08-04

## 背景

订阅目录按用户保存远程清单缓存，但浏览器快照、后端源缓存和 ComfyUI 原生更新通知曾分别刷新，导致页面刷新后仍可能展示旧目录，或者旧的远程响应覆盖新的缓存。

## 决策

- 保留按用户隔离、以 GitHub Contents API 的 ETag 和内容哈希校验的持久化源缓存；已登录 GitHub 时清单读取使用用户 token 走 Contents API（限流时回退 raw）；未登录或凭据 401 时优先使用带唯一强制刷新查询参数的 GitHub Raw CDN 请求（不占用按 IP 共享的匿名 API 配额），失败时回退匿名 Contents API，避免订阅功能因匿名 API 配额耗尽而不可用。
- 浏览器按后端返回的用户作用域保存版本化目录快照，只缓存订阅源和聚合工作流数据，不缓存凭据、操作日志或发布数据。快照只负责快速首屏和失败回退，不能作为刷新成功的依据；缓存版本变化时自动丢弃旧快照。
- 订阅页先通过单一 `GET /catalog` 请求读取后端持久化目录，并优先恢复当前用户的浏览器快照；已有快照时不显示阻塞式空白加载。远程校验使用 stale-while-revalidate：目录先可浏览，校验结果在后台收敛并原位更新。
- 每次 ComfyUI 进程启动后，每个用户首次需要目录校验时都会对全部订阅源执行一次强制远程校验；启用自动检查的宿主扩展与内置页面共享同一个后端 single-flight 任务，并在成功后记录进程内完成状态，因此重复打开面板不会反复执行强制校验。关闭自动检查时宿主不会自行触发网络请求，但用户打开订阅页仍会校验当前目录。失败不会记作完成，下一次检查仍可重试。后续打开订阅页会在后台执行 ETag 条件校验，确保同版本的更新日志、依赖改动和删除也能及时收敛，同时不阻塞首屏；手动刷新始终使用强制请求。
- “刷新全部”复用强制刷新接口；单源刷新、添加/移除订阅和发布者管理完成后的刷新都会使目录请求版本失效并等待新的结果。强制 API 请求不发送旧 ETag，并使用 `Cache-Control: no-cache`。
- 发布页所需的 GitHub 仓库、待恢复发布、仓库目录以及当前画布资源扫描只在用户进入发布或管理界面后加载，不参与订阅页首屏。
- 同一用户、同一订阅源的刷新仍由后端锁串行执行；前端目录请求使用 single-flight 和递增版本号，避免旧请求在强制刷新后回写旧数据。刷新接口返回远程刷新后的订阅源和聚合目录，避免再次读取尚未收敛的旧快照。
- ComfyUI 原生更新通知使用独立的每用户检查状态，不读取浏览器目录快照；自动检测默认开启，默认间隔 4 小时，可在 1–168 小时内配置。到期检查使用 ETag 条件请求进行远程验证（目录未变化返回 304，不占 API 主限流额度；优先 Contents API，限流时使用只读 Raw 回退），成功后才记录周期；网络或清单失败会在短暂退避后重试。Toast 按「工作流 + 版本」去重，每个版本只弹一次，满 7 天未下载最多再提醒一次；未下载的更新以顶栏按钮角标持续呈现。宿主根据后端返回的下一次检查时间调度检查，设置变更会立即重新计算。

## 结果

首次显示和后续重开都会立即展示当前用户最近的可用目录；每次 ComfyUI 启动仍会完成一次不受 CDN/ETag 旧缓存影响的强制远程校验，结果随后原位更新。重复打开订阅页不会执行发布者专用请求，目录的 ETag 条件校验只在后台运行。远程目录变化、用户主动操作和下载状态变化都会收敛到服务端真实状态。缓存是首屏优化和失败回退，不是刷新成功的依据；清理、配额不足、旧版本或隐私模式下的存储失败不会阻止实时刷新。
